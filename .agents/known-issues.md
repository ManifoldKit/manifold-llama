# Known issues

One line each: `symptom → root cause → fix`. Check this file before diagnosing anything.

- A sleep-based timing test passes locally (even under heavy local load) but fails in CI with a value far above its upper bound → GitHub macOS runners overshoot `Thread.sleep` by **~137ms per call**, versus 6-11ms total on a loaded local machine, so local load-testing does not model CI scheduling (seen 2026-07-25, PR #162: a ±40ms window around a 150ms mean went red at an observed 287ms) → for timing assertions, only bound the side that actually discriminates (usually a floor) and keep any ceiling very loose (~1s); never tune a tight symmetric tolerance against local measurements.
- A "fail-open lint clean" claim is vacuous because `bash ~/Repos/roryford/estate/scripts/lint-fail-open.sh` silently exits non-zero → that path does not exist; the script is not in estate's `main` at all (it lives on the unmerged `feat/prove-it-can-fail` branch, and a checked-out copy sits at `~/Repos/.worktrees/estate-ki-digest-fixed/scripts/lint-fail-open.sh`), and `bash <missing-path>` looks like a failed lint rather than a missing tool (seen 2026-07-25, #154) → run the worktree copy, and confirm the expected `lint-fail-open: N file(s) checked, M finding(s)` output line before reporting a result.
- Swift compiler crashes with "failed to produce diagnostic for expression" when building `LlamaBackend.generate()` → an inline ternary selecting between a closure literal and `nil` (`flag ? { … } : nil`) for a `driver.run()` trailing-closure argument, whether written inline or hoisted into a `let`; reproducible, not a flake (seen 2026-07-25, #142) → assign the closures with an explicit `if`/`else` into `var` bindings instead of a ternary.
- Grepping `.build/checkouts/ManifoldKit` returns stale API/line numbers that don't match the pinned core release → that checkout's `origin` is a **local bare cache** (`.build/repositories/ManifoldKit-*`), so it can sit a release behind the revision in `Package.resolved` (seen 2026-07-25: checkout at v0.72.0, `Package.resolved` pinned v0.73.0, and `GenerationRuntimeHints.history` appeared absent when it exists) → compare by **revision, not tag**: `describe --tags` can report an older tag (e.g. `v0.74.0-23-g3b4d1d2a` when `Package.resolved` says `0.75.0`) simply because the newer tag was never fetched into the local bare cache — that is a false alarm if the checkout HEAD equals the `revision` field. Verify with `git -C .build/checkouts/ManifoldKit rev-parse HEAD` against `Package.resolved`'s `revision`, then `git fetch https://github.com/ManifoldKit/ManifoldKit main --tags` and read the pinned revision explicitly via `git show <revision>:<path>`.
- Model-gated suites `XCTSkip` even though GGUFs are on disk under `~/Documents/Models/gguf/<model>/*.gguf` → test discovery is **non-recursive** (`contentsOfDirectory` on `~/Documents/Models/` only, e.g. `Tests/ManifoldLlamaTests/LlamaEmbeddingBackendTests.swift:32-48`) **and** gated behind `MANIFOLD_DISCOVER_LOCAL_MODELS=1`, so a nested model tree is invisible to it (seen 2026-07-28, #161/#172 — a worker's "69 skipped" was misread as a missing baseline) → set `LLAMA_TEST_MODEL=<explicit path>` to run them, and for live tool-call verification use `swift run manifold-tools-llama --model <path.gguf>` rather than expecting `swift test` to exercise a real model.
- A fresh worktree from the `wt` helper is based on a **stale local `main`**, so a "branched off main" claim can be several merges behind `origin/main` (seen 2026-07-28, #172: `wt` gave a5c109a/#157 when `origin/main` was already at #163) → after `wt <branch>`, always `git fetch origin` and check `git merge-base --is-ancestor origin/main HEAD`; reset to `origin/main` only while the branch still has no commits, otherwise rebase.
- `git rebase` (or any commit-creating git op) fails with `failed to write commit object` on an otherwise healthy tree → 1Password SSH commit signing (`op-ssh-sign`) is transiently locked/unavailable, not a git or disk problem; the error names the commit write, never the signing agent (seen 2026-07-28, #158/PR #171 mid-rebase) → `git rebase --abort` (safe — the branch and remote are untouched), unlock 1Password, and retry; do NOT work around it with `--no-gpg-sign`, which silently produces unsigned commits.
- Reverting a deliberate sabotage with `git checkout HEAD -- <file>` silently discards uncommitted real work in that file, because it restores to the last *commit*, not to the pre-sabotage working state (seen 2026-07-28, #158/PR #171: a fix round was reverted along with the sabotage and committed incomplete; the next gate caught it) → before sabotaging, either commit the good state first, or save the file (`cp`) and restore from that copy — and always re-verify the intended change is present in the commit object (`git show HEAD:<file> | grep`) before reporting a gate result.
- Model-gated suites FAIL (not skip) with `NSCocoaErrorDomain Code=260 "The file "Models" couldn't be opened"` naming an unrelated container path like `~/Library/Containers/com.apple.dt.ExternalViewService/Data/Documents/Models` → ManifoldKit v0.75.0 rewrote GGUF discovery into a recursive walk (#2393) and `modelSearchDirectories` appends `<container>/Data/Documents/Models` for every `~/Library/Containers/*` entry with no existence check, so non-existent roots hard-error; no model is ever loaded and the failure lands in 8-40ms during discovery, not during load (seen 2026-07-28, #166 — 9 clean skips became 6 failures with no local code change) → not a regression in this repo; run with an absolute `LLAMA_TEST_MODEL=<path>` to take the direct-override early return and bypass discovery entirely (the six tests all pass that way). Tracked upstream as ManifoldKit#2408.
- Coercing model-emitted text to `Double` and later serialising it aborts the process uncatchably (`libc++abi`, exit 134, `NSInvalidArgumentException: Invalid number value (NaN/infinite) in JSON write`) → `JSONSerialization.data(withJSONObject:)` raises an **ObjC exception** rather than throwing, so `try?` cannot catch it; and Apple's decoder is **asymmetric** on overflow — `[1e400]` is rejected by `JSONSerialization.jsonObject` but `[-1e400]`, `[-1e999]`, `{"a":-1e400}` and `[[-1e400]]` all decode to `-inf`, reaching the write path without ever passing through scalar coercion. `Double(String)` also accepts `nan`/`NaN`/`inf`/`infinity`/`-inf` and hex-float (`0x1p99999`) (seen 2026-07-28, #171/#175) → needs BOTH layers: reject non-finite in scalar coercion (keep the literal as text) AND gate the serialise call on `JSONSerialization.isValidJSONObject` (which does recurse into nested arrays/dicts). Testing note: an ObjC abort is not an `XCTAssert` failure, so assert the post-fix behaviour and prove the pre-fix crash out of band — a standalone binary, or sabotage the guard and watch XCTest report it as an *unexpected* failure.
